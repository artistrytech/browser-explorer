# Explorer Browser

Explorer(ファイル管理)を主画面に、テキスト編集(Monaco)と Git 管理を統合した
ローカル Web アプリ。

## 設定

初回セットアップ時は `config.jsonc.sample` を `config.jsonc` にコピーして作成し、
必要に応じてポートやトークンを調整する。JSONC 形式なので `//` コメントを書ける。

`host` / `port` / `clientPort` / `token` は再起動が必要なため `config.jsonc` で設定する。
一方 `commitFilesLimit` / `contextMenu` / `externalTools` / `diffTools` は初回起動時に
`config.jsonc` から DB へ取り込まれ、以後は画面右上の **設定** から編集する
(再起動なしで即時反映)。設定画面はタブ構成:

- **一般**: 表示モード・テーマ・エンコーディング・コミット変更ファイルの表示上限 など。
- **コンテキストメニュー**: 各メニュー項目の表示 / 非表示。
- **外部ツール**: 右クリックから起動するツール。対象種別 (ファイル/フォルダ) や
  対象拡張子で表示条件を絞り込み、起動前の確認要否を指定できる。拡張子ごとに
  ダブルクリック時の既定起動ツールも設定可 (未設定はアプリ内エディタ)。
  「プリセットから追加」で CMD / シェル / Chrome / VS Code などの雛形を挿入できる。
- **差分ツール**: WinMerge / Meld / VS Code などの外部差分ツール。

設定内容は設定画面の **エクスポート / インポート** で JSON として持ち出せる
(ブックマーク・リポジトリ一覧も含む)。外部ツールの起動に失敗した場合 (実行ファイルが
見つからない等) はトーストでエラー通知する。

## 起動

```bash
npm install
npm run dev     # server (127.0.0.1:5175) + client (127.0.0.1:5173) を並列起動
```

ブラウザで <http://127.0.0.1:5173/> を開く。カレントパスは URL の `?path=` に反映される。

### PWA としてインストールする (アプリ内タブ)

Chrome / Edge のアドレスバーのインストールボタン (またはメニューの「アプリとしてインストール」) で
PWA としてインストールできる。PWA は <http://127.0.0.1:5173/tabs.html> (アプリ内タブのシェル) で起動し、
アプリ内でタブを分けて複数の画面を並べて使える。ブラウザで `/tabs.html` を直接開いても同じように使える。

- 各タブは独立した画面として動く (表示中のフォルダ・ビュー・選択位置などはタブごとに別)。
- 別タブで開く操作 (サイドバーの Ctrl+クリック、「別ウィンドウで開く」など) はアプリ内の新しいタブで開く。
  Ctrl+クリックで別タブに開ける箇所 (サイドバー・Markdown プレビューのリンク・右クリックメニューの
  「Gitログ」「ファイル場所に移動」など) は、中クリック (ホイールクリック) でも別タブで開く。
- 新しいタブは表示中のタブと同じフォルダで開く。タブはドラッグで並べ替え、中クリックで閉じられる。
- タブの右クリックメニューから「他のタブをすべて閉じる」「右側のタブを閉じる」ができる。
- タブの構成 (各タブの URL) は保存され、次回起動時に復元する。
- エディタに未保存の変更があるタブを閉じるときは確認する。
- 登録したリポジトリはグループ分けでき、グループに入れたリポジトリを開いているタブは背景がグループの色になり、
  左端に短縮名のチップが付く。設定は左パネルの「リポジトリ」見出しの荷札ボタン (またはリポジトリの右クリック →
  「グループ分け…」、コマンドパレットの「リポジトリ: グループ分け」) から開くダイアログで行う。
  - グループは管理用の名前と色を持つ (名前は画面には出さない)。色は追加時に見分けやすい候補から自動で割り当て、
    色見本のクリックで変更できる。
  - リポジトリごとに所属グループと短縮名を設定する。どのグループにも入れない (未分類) こともできる。
  - 行の左端の ＝ をドラッグすると、リポジトリの並び (左パネルの一覧の順) を変えられる。
  - 左パネルのリポジトリ一覧の ● もグループの色になる。
- PWA のウィンドウで `/` が直接開いたとき (ブラウザで開いたリンクがアプリに取り込まれた場合など) は、
  自動でタブの画面に切り替え、開いていたフォルダをタブとして開く。既にアプリのウィンドウがあれば、
  そちらのタブとして開いて新しいウィンドウは閉じる。
- アプリのウィンドウを複数開いた場合、タブの構成を保存・復元するのは最初に開いたウィンドウだけ
  (閉じると次のウィンドウが引き継ぐ)。

| キー | 動作 |
| --- | --- |
| Ctrl+T (Alt+T) | 新しいタブ |
| Ctrl+W (Alt+W) | タブを閉じる |
| Ctrl+Tab / Ctrl+Shift+Tab, Ctrl+PageDown / Ctrl+PageUp | 次 / 前のタブ (ブラウザが先に使う環境では効かない) |
| Alt+1〜8 / Alt+9 | n 番目のタブ / 最後のタブ |
| F5 | 表示中のタブだけを読み込み直す (エディタに未保存の変更があれば確認する。Ctrl+R はウィンドウ全体を読み込み直す) |

Ctrl+T / Ctrl+W が効くのは PWA のウィンドウだけ (通常のブラウザのタブで `/tabs.html` を開いた場合は
ブラウザ自身のタブ操作になるので、Alt+T / Alt+W を使う)。

## 構成

```
config.jsonc     # ポート・API トークン (+ 各設定の初回 seed 値。コメント可)
data/app.db      # SQLite (設定・外部ツール・ブックマーク等の永続化)
data/logs.db     # SQLite (アプリログ。保存期間は設定で変更)
data/lsp/        # 言語サーバ用の作業フォルダ (参照マップ。jdtls など ${dataDir} を使うもの)
server/          # Express + simple-git + chokidar + better-sqlite3 + node-pty
client/          # React + Vite + Zustand + Monaco Editor + xterm.js + React Flow (+ dagre)
```

## 主な操作 (Windows 流キーバインド)

| キー | 動作 |
| --- | --- |
| Return / ダブルクリック | 開く |
| F2 | リネーム |
| Alt+↑ / Alt+← / Alt+→ | 上の階層 / 戻る / 進む (ブラウザ履歴連動) |
| Ctrl+C / Ctrl+X / Ctrl+V | コピー / 切り取り / 貼り付け (切り取り→貼付で移動) |
| Delete / Shift+Delete | ゴミ箱へ / 完全削除 |
| Ctrl+S / Ctrl+Shift+S | 保存 / すべて保存 (エディタ) |
| Ctrl+Shift+P (mac は ⌘+Shift+P) | コマンドパレット |
| Ctrl+` (日本語キーボードは Ctrl+@ も) | ターミナルの表示 / 非表示 |

- エンコーディング (UTF-8 / Shift_JIS / EUC-JP / UTF-16)・改行 (CRLF/LF/CR)・BOM は
  ステータスバーから切替。エディタ上部の「再読込」(保存の左) で開き直し、Ctrl+S で変換保存。
  未保存の編集がある状態で「再読込」を押したときは確認する。
- エディタで開いているファイルはタブごと (sessionStorage) に覚え、画面を読み込み直しても開き直す
  (内容はファイルから読み直すので、未保存の編集は引き継がない)。
- Markdown (.md 等) はエディタタブで開き、上部の「✎ 編集 / 👁 プレビュー」で表示を切り替える。
  ダブルクリックではプレビュー表示で開き (右クリック →「エディタで開く」は編集表示)、プレビューには未保存の編集も反映する。
  プレビュー中は拡大率 (− / + / Ctrl+ホイール / Ctrl+± / Ctrl+0) と全画面 (Esc で終了) も上部から操作できる。
- Git はシステムの git を使用。push/pull の認証は git 側 (credential helper / SSH agent) に委譲。
  HTTPS の認証で失敗した場合は、結果ダイアログの「サインインして再試行」で Git Credential Manager の
  サインイン画面 (ブラウザ / コード / トークン) を開いて再実行できる。
  クローンは新しいリポジトリで資格情報が未保存のことが多いため、最初からサインイン画面を許可して実行する。
- git worktree に対応。他のワークツリーでチェックアウト中のブランチはブランチ一覧に「ワークツリー」と表示し、
  切替・削除・一括同期の対象から外す (git が拒否するため)。右クリックやダブルクリックでそのワークツリーを開ける。
  「認証」の設定 (SSH 鍵・資格情報ヘルパー) は同じリポジトリのワークツリー同士で共有する。
- 設定・ブックマーク・リポジトリ一覧は SQLite に永続化。設定画面からエクスポート / インポート可。
- OS 連携: フォルダ/空白の右クリックに「Explorer(Finder)で開く」
  「コマンドプロンプト(ターミナル)で開く」(ホスト OS に応じて自動切替)。
  「アプリ内のターミナルで開く」もある (下記「ターミナル」)。
- ファイル/フォルダの右クリック「パスをコピー」で、リポジトリからの相対パス (Git 管理下のみ) とパスをコピーできる (相対パスを先に出す)。
  Windows では区切りが "/" と "\" のものを両方出す。複数選択時は 1 行に 1 つずつ並べてコピーする。
- フォルダ/空白の右クリック「追加」から新規ファイル / 新規フォルダを作れる。新規ファイルは拡張子をサブメニューで選ぶ。
  候補は過去に「新規ファイル」で作った拡張子の新しい順 10 件 (DB に記録。まだ無ければ .txt のみ)。
  「その他…」では拡張子も名前と一緒に入力する。
- 左パネルのプロジェクトツリー (Git リポジトリを開いているとき) の右クリックは、ファイルタブの一覧と同じメニューを出す。
  行以外の空白の右クリックは、リポジトリのルートを対象にしたファイルタブの空白と同じメニュー。
  フォルダのクリックで、ファイルタブの表示中のフォルダもそのフォルダにする (開いているタブは切り替えない)。

## 追加機能

- **コマンドパレット**: Ctrl+Shift+P で VSCode と同様の入力欄を開き、コマンドを絞り込んで実行する。
  日本語名のほか英語名でも絞り込める (`sync` で「同期」、`repo` で「リポジトリ」など)。
  - 同期 (「同期」ボタンと同じ) / 同期: Pull・Push・Fetch・一括・リモート (同期ダイアログをそのタブで開く)
  - ブランチ切り替え: 続けてローカルブランチの一覧 (バックアップブランチは除く) から選んで切り替える。名前で絞り込み。
    他のワークツリーで使用中のブランチは、選ぶとそのワークツリーを開く
  - ブランチ作成 / ブランチ名変更 / ブランチのバックアップ: ブランチタブのヘッダの「＋ ブランチ作成」「名前変更」「バックアップ」と同じ
    (名前変更・バックアップの対象は現在のブランチ)
  - リポジトリ / クイックアクセス (続けて一覧から選ぶ。名前で絞り込み)。「(別タブ)」付きは別タブで開く
  - リポジトリ: グループ分け (グループの設定ダイアログを開く)
  - レビュー (未コミット): レビュータブの「未コミットの変更」を開く
  - コミット: コミットタブを開いてメッセージ欄にフォーカスする
  - AI チャット: AI チャットのウィンドウを開く
  - ターミナル: アプリ内のターミナルを開く / 新しいターミナル: 表示中のフォルダで新しいターミナルを開く
  - ↑↓ で選択、Enter で実行、Esc で閉じる。一覧を選んだ後は入力が空の Backspace でコマンドの一覧へ戻る
- **ログを表示**: Git 管理下のファイル/フォルダを右クリック → 対象パスで絞り込んだ履歴
  (ファイルはリネーム追跡 `--follow`)。「絞り込み解除」で全体表示へ。
  ログタブ上部のプルダウンを「コミット指定」に切り替えると、ハッシュ (短縮形可) を入力して Enter で
  そのコミットと祖先のログを表示する (パス絞り込みとは排他。URL の `logcommit=` で復元)。
- **Git グラフ**: Git パネルの「ログ」タブ (絞り込みなし時) はコミット DAG をレーン描画。
  ref チップ表示、右クリックでハッシュ値をコピー / checkout / reset / cherry-pick / タグ付け。
  cherry-pick は確認ダイアログで「即コミットする (`--no-commit`)」「元のコミット ID を
  メッセージに含める (`-x`。即コミット時のみ選択可)」を選んでから実行。
- **レビュー**: レビュータブの「＋ レビュー作成」で、対象 (HEAD / ブランチ / コミットのハッシュを直接入力) と
  取り込み先のブランチを選んで差分にコメントする。比較方法は「3 点比較 (分岐点から。`git diff base...head`)」と
  「2 点比較 (先端どうしを直接比較。`git diff base..head`)」から選べる。2 点比較では取り込み先が進むと
  「最新に更新」のバナーが出る。コミット指定のレビューはブランチが削除されても自動クローズしない。
- **競合を解消**: マージ/リベース/cherry-pick 進行中は Git パネルにバナー表示、
  フォルダ右クリックに「競合を解消…」。競合一覧 → 3-way 解消ツール
  (自分/相手の対比 + Monaco の編集可能な統合結果ペイン)。バイナリ・片側削除は片側採用のみ。
- **2 画面で整理**: ツールバーの ⧉ (または右クリック「開く › 2 画面で整理…」) で、左右 2 つのフォルダを並べた
  ダイアログを開く。ドラッグ&ドロップ (反対側のペイン・フォルダ行・パンくずへ。Ctrl でコピー) または
  F5 (コピー) / F6 (移動) で送ると、毎回確認ダイアログを出す。確認では移動 / コピーを選び直せ、同名の衝突は
  項目ごと (またはまとめて) に「上書き / 両方残す (連番) / スキップ」を選ぶ。上書きされる側はゴミ箱へ送る。
  移動したファイルをエディタで開いていれば、タブは移動先に付け替わる。
- **Git init…**: Git 管理外のフォルダ/空白の右クリック (または「コミット」タブ等の「git init…」) から。
  最初のブランチ名 (既定は親の設定の init.defaultBranch、無ければ main) を指定でき、
  「このリポジトリだけ別のユーザ名 / メールアドレスを使う」で親の設定を上書きできる (リポジトリの config に保存)。
  上書きするときは、登録済みの他のリポジトリで使っているユーザ名 / メールアドレスを候補から選べる。
- **Git Clone…**: Git 管理外のフォルダ/空白の右クリックから。ブランチ指定 / shallow /
  サブモジュール対応、進捗を WebSocket でストリーム表示。

## AI チャット (Codex / Claude)

ツールバーの 🤖 (またはコマンドパレットの「AI チャット」) で、VSCode の拡張機能のように Codex / Claude の CLI と
対話するウィンドウを開く。🤖 は表示 / 非表示の切り替えで、表示中はボタンを強調する。
開いているかはタブごとに覚えておき、画面を読み込み直したときに開き直す (別タブには引き継がない)。

- **ウィンドウ**: モードレス (開いたまま背後の画面を操作できる)。タイトルバーのドラッグで移動、四辺・四隅のドラッグで
  サイズ変更。位置とサイズは次に開いたときに復元する。タイトルバーのダブルクリックで本体を折り畳み、
  タイトルバーだけの表示にする (もう一度ダブルクリックで戻す。折り畳み中も移動と幅の変更はできる)。
- **右パネルに固定**: タイトルバーのボタンで、フローティングではなくメイン領域の右のパネルに固定して表示できる
  (もう一度押すとフローティングに戻る)。パネルの幅は境界のドラッグで変えられ、表示方法と幅は次に開いたときも引き継ぐ。
- **入力欄の高さ**: 会話と送信欄の境界をドラッグすると送信欄 (依頼の入力欄) の高さを変えられる (会話の部分は最低限残す)。
  高さは次に開いたときも引き継ぎ、境界のダブルクリックで元の高さに戻る。
- **使える AI**: `codex` / `claude` のうち PATH が通っているものだけ選べる (どちらも無ければ送信できない)。
  CLI を非対話モード (`codex exec --json` / `claude -p --output-format stream-json`) で起動し、依頼文は標準入力で渡す。
- **Box**: 会話を自由にまとめる単位。上部のドロップダウンで切り替える (開くと名前・フォルダで絞り込め、↑↓ と Enter でも選べる)。
  ドロップダウンの「＋ 新規 Box」で名前とベースフォルダ (既定は表示中のフォルダ) を指定して作る。
  名前の既定は「フォルダ名 + 作成日時」で、フォルダ名はベースフォルダがリポジトリ内ならリポジトリのルートのフォルダ名、
  それ以外はベースフォルダのフォルダ名。名前はドロップダウンの右のペンのアイコン (またはドロップダウンの一覧の右クリック)
  で後から変えられる。1 つの Box の中で Codex と Claude のどちらも使える。
  AI チャットを開くと、ファイル一覧で表示中のフォルダをベースフォルダにする Box のうち最後に使ったもの
  (最新の依頼が新しいもの) を自動で選ぶ。表示中のフォルダの Box が無ければ、親のフォルダ (近い方を優先) の Box から選ぶ
  (リポジトリのサブフォルダを表示中でも、リポジトリのルートの Box が開く)。それも無く、表示中のフォルダが Git リポジトリ内なら、
  同じリポジトリの他のフォルダの Box から選ぶ。該当する Box が無ければ「会話履歴はありません」と「＋ 新規 Box」のボタンを表示する
  (他のフォルダの Box はドロップダウンから選べる)。
- **ベースフォルダ**: CLI の作業フォルダ。見出しのフォルダ名の右のペンのアイコンで会話の途中でも変えられるが、変えた後の依頼はすべて新しい会話になる
  (CLI の会話の再開はフォルダ単位のため)。会話の一覧には変更した位置に区切りを出す。
- **依頼のオプション**
  - AI: Codex / Claude をプルダウンで選ぶ (PATH に無いものは選べない)。
  - 会話: 「継続」(その AI の最後の会話の続き) か「新規」(新しい会話) をプルダウンで選ぶ。異なる AI 間で会話は引き継げない
    (Codex の会話を Claude で続けることはできない)。会話には Box 内の通し番号 (#1, #2 …) が付く。
    ページを開いてから初めて表示する送信欄は、続けられる会話があっても「新規」から始まる
    (閉じて開き直したときや、他の Box に切り替えたときは「継続」が既定)。
  - モデル: 設定 → AI に登録したモデル名から選ぶ (未選択なら CLI の既定)。
  - effort: Codex は low〜ultra、Claude は low〜max (未選択なら CLI の既定)。
  - 権限: Codex はサンドボックス、Claude は権限モード (未選択なら設定 → AI の既定値)。会話の一覧に実行時の値を表示する。
  - AI・モデル・effort・権限の選択は Box ごとに保存し、Box を開いたときに復元する
    (選択を保存していない Box は、最後に使った選択から始まる)。
  - スキル: 送信欄の左下の「スキル ▾」で、選んでいる AI が使えるスキルを一覧から選ぶ (スキル名で絞り込め、↑↓ と Enter でも選べる)。
    Claude は依頼の先頭に `/スキル名` を入れ (先頭に別のスキルがあれば置き換える)、Codex はカーソルの位置に `$スキル名` を入れる。
    一覧は開くたびに読み直す。探す場所は、Claude が `.claude/skills/*/SKILL.md` と `.claude/commands/*.md`、
    Codex が `.agents/skills` と `.codex/skills` (`.system` の同梱スキルを含む)。それぞれベースフォルダからリポジトリのルートまでの
    各フォルダとホーム (`~/.claude`・`CLAUDE_CONFIG_DIR`、`~/.agents`・`~/.codex`・`CODEX_HOME`) を探し、同じ名前はプロジェクトのものを優先する。
  - Ctrl+Enter で送信。実行中は「停止」で中断できる (子プロセスごと終了する)。
- **AI の出力**: 返答は Markdown で表示し、コマンド実行・ファイル変更・ツール呼び出しは 1 行ずつ (クリックで中身を展開)。
  出力は 1 回分ずつ見出しのクリックで折り畳め、「すべて折り畳む / すべて展開」もある。⧉ で返答の本文をコピー。
  Box を開いたときは最新以外の出力を折り畳んで表示し、依頼を送るとそれまでの出力 (開いていたものも) を折り畳む。
  途中経過はサーバの DB に保存しながら WebSocket で全タブへ送るので、画面を読み込み直しても続きが見える。
- **表示件数**: 会話は新しい方から 10 件ずつ表示し、古いものは上端の「さらに読み込む」で遡る (見ていた位置は保つ)。
- **削除**: 依頼の右上の ⋯ (または依頼・出力の見出しの右クリック) から、「このメッセージを削除」
  「このメッセージと、これより古い会話を削除」を選ぶ。実行中の会話は削除できない。消えるのはこのアプリの記録だけで、
  CLI 側の会話の記録は残る (「継続」で送ると削除した内容も文脈に含まれる)。
- **設定 → AI**
  - モデル: AI ごとにテキストエリアへ 1 行 1 つ書く。
    Codex は「codex debug models から取得」で CLI のモデル一覧を出し、クリックで追加できる。
    Claude は `{モデル系列}-{メジャー}-{マイナー}` (例: `opus-5-5`) を組み立てて追加できる (メジャー・マイナーは入力したときだけ付く)。
    CLI に認識されないモデル名だとエラーになるので、その場合は最新のモデル名を確認する。
  - 権限の既定値: Codex のサンドボックス (初期値 `workspace-write`)、Claude の権限モード (初期値 `acceptEdits`)。
    依頼ごとの指定は送信欄で行う。
- 保存先: `data/app.db` の `ai_boxes` / `ai_turns`。CLI 側の会話の記録は各 CLI の保存先 (`~/.codex` / `~/.claude`) に残る。

## ターミナル

ツールバーのターミナルのアイコン (またはコマンドパレットの「ターミナル」、Ctrl+`) で、画面の中にターミナルを開く。
シェルはサーバ側で疑似端末 (node-pty。Windows は ConPTY) として起動し、入出力を WebSocket (`/ws/terminal`) で中継する。
画面の描画は xterm.js。

- **表示位置**: タイトルバーのボタンで「下パネルに固定」「右パネルに固定」「フローティング」を切り替える。
  パネルの高さ・幅は境界のドラッグで変えられ、表示位置・大きさ (フローティングは位置とサイズ) は次に開いたときも引き継ぐ。
  切り替えても画面の内容と実行中のコマンドはそのまま。
- **タブ**: 複数のターミナルをタブで開ける。「＋」で既定のシェル、隣の「▾」でシェルを選んで開く。作業フォルダはファイル一覧で
  表示中のフォルダ (フォルダの右クリック「アプリ内のターミナルで開く」ならそのフォルダ)。タブ名は作業フォルダ名で、
  ダブルクリック (または右クリック) で変えられる。タブの ✕・中クリックでシェルを終了する (シェルから起動したプロセスも終了する)。
  最後のタブを閉じる (または `exit` で終了する) とパネルも閉じる。
- **シェル**: Windows はコマンドプロンプト / PowerShell / PowerShell 7 / Git Bash / WSL のうち見つかったもの、
  Mac / Linux はログインシェル (`$SHELL -l`) と `/etc/shells` のシェル。既定は 設定 → ターミナル で選ぶ
  (初期値は Windows がコマンドプロンプト、それ以外がログインシェル)。
- **コピー / 貼り付け**: 文字を選択して Ctrl+C (Mac は ⌘C) でコピー (選択が無ければシェルへの Ctrl+C = 中断)。
  Ctrl+V (⌘V) で貼り付け。Ctrl+Shift+C / V も使える。右クリックのメニューにコピー / 貼り付け / すべて選択 / 画面をクリア。
- **共有と復元**: ターミナルはサーバのメモリにあり、全タブで共有する (複数のタブで同じターミナルを開いたときは、
  最後に操作したタブの大きさに合わせる)。画面を読み込み直しても、直近の出力 (最大 512K 文字) から表示を復元する
  (読み込み直す前にそのタブで開いていれば、ターミナルのパネルも開き直す)。
  サーバを再起動するとターミナルはすべて終了する (開いていたタブにはその旨を表示する)。
- **注意**: このサーバにつながるものは任意のコマンドを実行できる。サーバは 127.0.0.1 だけで待ち受け、
  ターミナルの接続にはトークンに加えて Host / Origin が localhost であることを求める。
- **インストール**: node-pty は Windows (x64 / arm64)・Mac (Intel / Apple Silicon) のビルド済みのバイナリを同梱しているので、
  ビルドツールは不要 (Linux はインストール時にビルドするため、gcc / make / python が必要)。
  ネイティブモジュールなので、Windows と Mac で `node_modules` を共有せず、それぞれで `npm install` する。

## 参照マップ (コードの静的解析)

エディタでクラス・メソッド・関数の名前にカーソルを置き、右クリック →「参照マップを表示」(または Shift+Alt+H) で、
そのシンボルを中心に参照元 (左) と参照先 (右) をたどるグラフを「🕸 シンボル名」のタブに開く。
解析は言語サーバ (LSP) で行う。言語サーバの無い言語は AI (Claude / Codex) に作らせることもできる。

- **調べられる関係**: 呼び出し元 / 呼び出し先 (callHierarchy)、参照元 (references。参照している関数・メソッドごとにまとめる)、
  親の型 / 子の型 (typeHierarchy)。言語サーバが対応していないものはその旨を表示する
  (呼び出し階層に対応していないときは、呼び出し元の代わりに参照元を出す)。
- **操作**: ノードの ◀ / ▶ で参照元 / 参照先を 1 段ずつ展開し、もう一度押すと畳む (クラス・インターフェイス等の ◀ は参照元)。
  右クリックで展開する関係を選べるほか、「このシンボルを起点に作り直す」「マップから外す」など。
  ノードのダブルクリックで定義を、エッジのクリックで呼び出し / 参照している箇所を開く (複数あるときはエッジの右クリックで選ぶ)。
  エッジの「×n」は箇所の数。線は 実線 = 呼び出し / 破線 = 参照 / 太線 = 継承。
  ライブラリ・標準ライブラリなどプロジェクトの外のシンボルは、既定では隠す (「ライブラリも表示」で出す)。
  「Mermaid をコピー」で表示中のマップを Mermaid の flowchart としてコピーできる。
- **言語サーバ**: 設定 → コード解析 で、拡張子ごとに使う言語サーバを指定する (上から順に最初に当てはまる有効なもの)。
  初期値は次のプリセット。コマンドは PATH と、プロジェクトの `node_modules/.bin` から探す。見つからないものは設定画面にインストール方法を出す。

  | 言語 | コマンド | インストール例 |
  | --- | --- | --- |
  | TypeScript / JavaScript | `typescript-language-server --stdio` | `npm install -g typescript-language-server typescript` |
  | Python | `pyright-langserver --stdio` | `npm install -g pyright` |
  | Java | `jdtls -data ${dataDir}` | JDK 21 以降 + Eclipse JDT LS |
  | C# | `csharp-ls` | `dotnet tool install --global csharp-ls` |
  | Go | `gopls` | `go install golang.org/x/tools/gopls@latest` |
  | Rust | `rust-analyzer` | `rustup component add rust-analyzer` |
  | C / C++ | `clangd` | LLVM (compile_commands.json があると正確) |
  | PHP | `intelephense --stdio` | `npm install -g intelephense` |
  | Ruby | `ruby-lsp` | `gem install ruby-lsp` |
  | Kotlin / Swift / Dart / Lua | `kotlin-language-server` / `sourcekit-lsp` / `dart language-server` / `lua-language-server` | 各 SDK・リリース |

  言語サーバは「言語サーバ × プロジェクトのフォルダ」ごとにサーバ側で起動し、30 分使わないと止める (設定画面から止めることもできる)。
  プロジェクトのフォルダは、ファイルから近い親で目印 (`tsconfig.json`・`pom.xml`・`*.csproj` 等) のあるフォルダ (無ければ Git のリポジトリ)。
  起動直後はプロジェクトの読み込み (インデックス作成) に時間がかかり、その間は結果が足りないことがある (画面に表示する)。
  引数の `${root}` はプロジェクトのフォルダ、`${dataDir}` は言語サーバ用の作業フォルダ (`data/lsp/` 配下) に展開する。
- **AI で作成**: 言語サーバが無いとき (またはタブの「AI で作成 ▾」から)、Claude / Codex の CLI に読み取り専用で依頼し、
  呼び出し元 / 呼び出し先を JSON で返させてマップにする (Claude は Read / Grep / Glob だけを許可、Codex は read-only サンドボックス)。
  1 回の依頼に数十秒〜数分かかり、結果は言語サーバほど正確ではない (行番号の単位で、存在しない参照が混ざることもある)。
  AI チャットの Box には記録しない。

## アプリログ (動作ログの記録と確認)

サーバ・クライアントの動作ログを `data/logs.db` (SQLite。設定用の `app.db` とは別) に記録し、
ツールバーの 🩺 (または設定 → 一般 → 「アプリログを開く」) から画面上で確認・検索できる。

- **ID による紐づけ**
  - **セッション ID**: ブラウザのタブ単位 (sessionStorage)。全 API に `x-session-id`、WS に `?session=` で送る。
  - **リクエスト ID**: HTTP リクエストごとにサーバが発行。レスポンスの `x-request-id` とエラー JSON の
    `requestId` に含める。エラートーストにも表示され、クリックするとそのリクエストのログが開く。
- **記録内容**: アクセスログ (メソッド / パス / ステータス / 所要時間)、エラー (スタック付き)、
  未捕捉例外 (`uncaughtException` / `unhandledRejection`)、WS の接続/切断、ブラウザ側の未捕捉例外や
  トーストに出したエラー (`POST /api/log/client`)。
- **検索**: 文字列 (メッセージ・詳細)、レベル (debug/info/warn/error 以上)、発生元 (サーバ/クライアント)、
  セッション ID (候補付き。「このタブのみ」ボタンあり)、リクエスト ID、期間。行クリックで詳細 (JSON・スタック) を展開。
- **保存期間**: 既定 30 日。設定 → 一般 → 「アプリログの保存期間 (日)」で変更。起動時と 1 時間ごとに古い行を削除する。
  「全削除」で即時に全消去も可能。
- 開発時、トーストに「サーバーに接続できません」と出る場合は Vite のプロキシがサーバに繋げていない
  (`node --watch` の再起動中、またはクラッシュ)。クラッシュならその直前のログが `uncaughtException` として残る。

## セキュリティ (plan §2.2)

- 127.0.0.1 のみで待受、Host/Origin 検証、`x-app-token` によるトークン必須。
- アプリ内のターミナル (`/ws/terminal`) は任意のコマンドを実行できるため、トークンに加えて Host / Origin も検証する。
- 削除は既定でゴミ箱送り (完全削除は確認付きの明示操作のみ)。
