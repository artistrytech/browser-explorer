# Explorer Browser

Explorer(ファイル管理)を主画面に、テキスト編集(Monaco)と Git 管理を統合した
ローカル Web アプリ。

## 設定

初回セットアップ時は `config.jsonc.sample` を `config.jsonc` にコピーして作成し、
必要に応じてポートやトークンを調整する。JSONC 形式なので `//` コメントを書ける。

`host` / `port` / `clientPort` / `token` は再起動が必要なため `config.jsonc` で設定する。
一方 `commitFilesLimit` / `contextMenu` / `externalTools` / `diffTools` は初回起動時に
`config.jsonc` から DB へ取り込まれ、以後は画面右上の **設定** から編集する
(再起動なしで即時反映)。設定画面はタブ構成:

- **一般**: 表示モード・テーマ・エンコーディング・コミット変更ファイルの表示上限 など。
- **コンテキストメニュー**: 各メニュー項目の表示 / 非表示。
- **外部ツール**: 右クリックから起動するツール。対象種別 (ファイル/フォルダ) や
  対象拡張子で表示条件を絞り込み、起動前の確認要否を指定できる。拡張子ごとに
  ダブルクリック時の既定起動ツールも設定可 (未設定はアプリ内エディタ)。
  「プリセットから追加」で CMD / シェル / Chrome / VS Code などの雛形を挿入できる。
- **差分ツール**: WinMerge / Meld / VS Code などの外部差分ツール。

設定内容は設定画面の **エクスポート / インポート** で JSON として持ち出せる
(ブックマーク・リポジトリ一覧も含む)。外部ツールの起動に失敗した場合 (実行ファイルが
見つからない等) はトーストでエラー通知する。

## 起動

```bash
npm install
npm run dev     # server (127.0.0.1:5175) + client (127.0.0.1:5173) を並列起動
```

ブラウザで <http://127.0.0.1:5173/> を開く。カレントパスは URL の `?path=` に反映される。

### PWA としてインストールする (アプリ内タブ)

Chrome / Edge のアドレスバーのインストールボタン (またはメニューの「アプリとしてインストール」) で
PWA としてインストールできる。PWA は <http://127.0.0.1:5173/tabs.html> (アプリ内タブのシェル) で起動し、
アプリ内でタブを分けて複数の画面を並べて使える。ブラウザで `/tabs.html` を直接開いても同じように使える。

- 各タブは独立した画面として動く (表示中のフォルダ・ビュー・選択位置などはタブごとに別)。
- 別タブで開く操作 (サイドバーの Ctrl+クリック、「別ウィンドウで開く」など) はアプリ内の新しいタブで開く。
  Ctrl+クリックで別タブに開ける箇所 (サイドバー・Markdown プレビューのリンク・右クリックメニューの
  「Gitログ」「ファイル場所に移動」など) は、中クリック (ホイールクリック) でも別タブで開く。
- 新しいタブは表示中のタブと同じフォルダで開く。タブはドラッグで並べ替え、中クリックで閉じられる。
- タブの右クリックメニューから「他のタブをすべて閉じる」「右側のタブを閉じる」ができる。
- タブの構成 (各タブの URL) は保存され、次回起動時に復元する。
- エディタに未保存の変更があるタブを閉じるときは確認する。
- 登録したリポジトリはグループ分けでき、グループに入れたリポジトリを開いているタブは背景がグループの色になり、
  左端に短縮名のチップが付く。設定は左パネルの「リポジトリ」見出しの荷札ボタン (またはリポジトリの右クリック →
  「グループ分け…」、コマンドパレットの「リポジトリ: グループ分け」) から開くダイアログで行う。
  - グループは管理用の名前と色を持つ (名前は画面には出さない)。色は追加時に見分けやすい候補から自動で割り当て、
    色見本のクリックで変更できる。
  - リポジトリごとに所属グループと短縮名を設定する。どのグループにも入れない (未分類) こともできる。
  - 行の左端の ＝ をドラッグすると、リポジトリの並び (左パネルの一覧の順) を変えられる。
  - 左パネルのリポジトリ一覧の ● もグループの色になる。
- PWA のウィンドウで `/` が直接開いたとき (ブラウザで開いたリンクがアプリに取り込まれた場合など) は、
  自動でタブの画面に切り替え、開いていたフォルダをタブとして開く。既にアプリのウィンドウがあれば、
  そちらのタブとして開いて新しいウィンドウは閉じる。
- アプリのウィンドウを複数開いた場合、タブの構成を保存・復元するのは最初に開いたウィンドウだけ
  (閉じると次のウィンドウが引き継ぐ)。

| キー | 動作 |
| --- | --- |
| Ctrl+T (Alt+T) | 新しいタブ |
| Ctrl+W (Alt+W) | タブを閉じる |
| Ctrl+Tab / Ctrl+Shift+Tab, Ctrl+PageDown / Ctrl+PageUp | 次 / 前のタブ (ブラウザが先に使う環境では効かない) |
| Alt+1〜8 / Alt+9 | n 番目のタブ / 最後のタブ |
| F5 | 表示中のタブだけを読み込み直す (エディタに未保存の変更があれば確認する。Ctrl+R はウィンドウ全体を読み込み直す) |

Ctrl+T / Ctrl+W が効くのは PWA のウィンドウだけ (通常のブラウザのタブで `/tabs.html` を開いた場合は
ブラウザ自身のタブ操作になるので、Alt+T / Alt+W を使う)。

## 構成

```
config.jsonc     # ポート・API トークン (+ 各設定の初回 seed 値。コメント可)
data/app.db      # SQLite (設定・外部ツール・ブックマーク等の永続化)
data/logs.db     # SQLite (アプリログ。保存期間は設定で変更)
server/          # Express + simple-git + chokidar + better-sqlite3
client/          # React + Vite + Zustand + Monaco Editor
```

## 主な操作 (Windows 流キーバインド)

| キー | 動作 |
| --- | --- |
| Return / ダブルクリック | 開く |
| F2 | リネーム |
| Alt+↑ / Alt+← / Alt+→ | 上の階層 / 戻る / 進む (ブラウザ履歴連動) |
| Ctrl+C / Ctrl+X / Ctrl+V | コピー / 切り取り / 貼り付け (切り取り→貼付で移動) |
| Delete / Shift+Delete | ゴミ箱へ / 完全削除 |
| Ctrl+S / Ctrl+Shift+S | 保存 / すべて保存 (エディタ) |
| Ctrl+Shift+P (mac は ⌘+Shift+P) | コマンドパレット |

- エンコーディング (UTF-8 / Shift_JIS / EUC-JP / UTF-16)・改行 (CRLF/LF/CR)・BOM は
  ステータスバーから切替。「再読込」で開き直し、Ctrl+S で変換保存。
- Git はシステムの git を使用。push/pull の認証は git 側 (credential helper / SSH agent) に委譲。
  HTTPS の認証で失敗した場合は、結果ダイアログの「サインインして再試行」で Git Credential Manager の
  サインイン画面 (ブラウザ / コード / トークン) を開いて再実行できる。
  クローンは新しいリポジトリで資格情報が未保存のことが多いため、最初からサインイン画面を許可して実行する。
- git worktree に対応。他のワークツリーでチェックアウト中のブランチはブランチ一覧に「ワークツリー」と表示し、
  切替・削除・一括同期の対象から外す (git が拒否するため)。右クリックやダブルクリックでそのワークツリーを開ける。
  「認証」の設定 (SSH 鍵・資格情報ヘルパー) は同じリポジトリのワークツリー同士で共有する。
- 設定・ブックマーク・リポジトリ一覧は SQLite に永続化。設定画面からエクスポート / インポート可。
- OS 連携: フォルダ/空白の右クリックに「Explorer(Finder)で開く」
  「コマンドプロンプト(ターミナル)で開く」(ホスト OS に応じて自動切替)。

## 追加機能

- **コマンドパレット**: Ctrl+Shift+P で VSCode と同様の入力欄を開き、コマンドを絞り込んで実行する。
  日本語名のほか英語名でも絞り込める (`sync` で「同期」、`repo` で「リポジトリ」など)。
  - 同期 (「同期」ボタンと同じ) / 同期: Pull・Push・Fetch・一括・リモート (同期ダイアログをそのタブで開く)
  - リポジトリ / クイックアクセス (続けて一覧から選ぶ。名前で絞り込み)。「(別タブ)」付きは別タブで開く
  - リポジトリ: グループ分け (グループの設定ダイアログを開く)
  - レビュー (未コミット): レビュータブの「未コミットの変更」を開く
  - コミット: コミットタブを開いてメッセージ欄にフォーカスする
  - AI チャット: AI チャットのウィンドウを開く
  - ↑↓ で選択、Enter で実行、Esc で閉じる。一覧を選んだ後は入力が空の Backspace でコマンドの一覧へ戻る
- **ログを表示**: Git 管理下のファイル/フォルダを右クリック → 対象パスで絞り込んだ履歴
  (ファイルはリネーム追跡 `--follow`)。「絞り込み解除」で全体表示へ。
- **Git グラフ**: Git パネルの「ログ」タブ (絞り込みなし時) はコミット DAG をレーン描画。
  ref チップ表示、右クリックで checkout / reset / cherry-pick / タグ付け。
  cherry-pick は確認ダイアログで「即コミットする (`--no-commit`)」「元のコミット ID を
  メッセージに含める (`-x`。即コミット時のみ選択可)」を選んでから実行。
- **競合を解消**: マージ/リベース/cherry-pick 進行中は Git パネルにバナー表示、
  フォルダ右クリックに「競合を解消…」。競合一覧 → 3-way 解消ツール
  (自分/相手の対比 + Monaco の編集可能な統合結果ペイン)。バイナリ・片側削除は片側採用のみ。
- **2 画面で整理**: ツールバーの ⧉ (または右クリック「開く › 2 画面で整理…」) で、左右 2 つのフォルダを並べた
  ダイアログを開く。ドラッグ&ドロップ (反対側のペイン・フォルダ行・パンくずへ。Ctrl でコピー) または
  F5 (コピー) / F6 (移動) で送ると、毎回確認ダイアログを出す。確認では移動 / コピーを選び直せ、同名の衝突は
  項目ごと (またはまとめて) に「上書き / 両方残す (連番) / スキップ」を選ぶ。上書きされる側はゴミ箱へ送る。
  移動したファイルをエディタで開いていれば、タブは移動先に付け替わる。
- **Git Clone…**: Git 管理外のフォルダ/空白の右クリックから。ブランチ指定 / shallow /
  サブモジュール対応、進捗を WebSocket でストリーム表示。

## AI チャット (Codex / Claude)

ツールバーの 🤖 (またはコマンドパレットの「AI チャット」) で、VSCode の拡張機能のように Codex / Claude の CLI と
対話するウィンドウを開く。🤖 は表示 / 非表示の切り替えで、表示中はボタンを強調する。

- **ウィンドウ**: モードレス (開いたまま背後の画面を操作できる)。タイトルバーのドラッグで移動、四辺・四隅のドラッグで
  サイズ変更。位置とサイズは次に開いたときに復元する。左側の Box の一覧と会話の境界をドラッグすると一覧の幅を変えられ、
  ☰ で一覧を隠せる。
- **右パネルに固定**: タイトルバーのボタンで、フローティングではなくメイン領域の右のパネルに固定して表示できる
  (もう一度押すとフローティングに戻る)。パネルの幅は境界のドラッグで変えられ、表示方法と幅は次に開いたときも引き継ぐ。
- **使える AI**: `codex` / `claude` のうち PATH が通っているものだけ選べる (どちらも無ければ送信できない)。
  CLI を非対話モード (`codex exec --json` / `claude -p --output-format stream-json`) で起動し、依頼文は標準入力で渡す。
- **Box**: 会話を自由にまとめる単位。「＋ 新規 Box」で名前とベースフォルダ (既定は表示中のフォルダ) を指定して作る。
  名前の既定は「フォルダ名 + 作成日時」で、フォルダ名はベースフォルダがリポジトリ内ならリポジトリのルートのフォルダ名、
  それ以外はベースフォルダのフォルダ名。名前は一覧のダブルクリック・右クリック・見出しのペンのアイコンで後から変えられる。
  1 つの Box の中で Codex と Claude のどちらも使える。
- **ベースフォルダ**: CLI の作業フォルダ。見出しのフォルダ名の右のペンのアイコンで会話の途中でも変えられるが、変えた後の依頼はすべて新しい会話になる
  (CLI の会話の再開はフォルダ単位のため)。会話の一覧には変更した位置に区切りを出す。
- **依頼のオプション**
  - AI: Codex / Claude をプルダウンで選ぶ (PATH に無いものは選べない)。
  - 会話: 「継続」(その AI の最後の会話の続き) か「新規」(新しい会話) をプルダウンで選ぶ。異なる AI 間で会話は引き継げない
    (Codex の会話を Claude で続けることはできない)。会話には Box 内の通し番号 (#1, #2 …) が付く。
  - モデル: 設定 → AI に登録したモデル名から選ぶ (未選択なら CLI の既定)。
  - effort: Codex は low〜ultra、Claude は low〜max (未選択なら CLI の既定)。
  - 権限: Codex はサンドボックス、Claude は権限モード (未選択なら設定 → AI の既定値)。会話の一覧に実行時の値を表示する。
  - Ctrl+Enter で送信。実行中は「停止」で中断できる (子プロセスごと終了する)。
- **AI の出力**: 返答は Markdown で表示し、コマンド実行・ファイル変更・ツール呼び出しは 1 行ずつ (クリックで中身を展開)。
  出力は 1 回分ずつ見出しのクリックで折り畳め、「すべて折り畳む / すべて展開」もある。⧉ で返答の本文をコピー。
  途中経過はサーバの DB に保存しながら WebSocket で全タブへ送るので、画面を読み込み直しても続きが見える。
- **設定 → AI**
  - モデル: AI ごとにテキストエリアへ 1 行 1 つ書く。
    Codex は「codex debug models から取得」で CLI のモデル一覧を出し、クリックで追加できる。
    Claude は `{モデル系列}-{メジャー}-{マイナー}` (例: `opus-5-5`) を組み立てて追加できる (メジャー・マイナーは入力したときだけ付く)。
    CLI に認識されないモデル名だとエラーになるので、その場合は最新のモデル名を確認する。
  - 権限の既定値: Codex のサンドボックス (初期値 `workspace-write`)、Claude の権限モード (初期値 `acceptEdits`)。
    依頼ごとの指定は送信欄で行う。
- 保存先: `data/app.db` の `ai_boxes` / `ai_turns`。CLI 側の会話の記録は各 CLI の保存先 (`~/.codex` / `~/.claude`) に残る。

## アプリログ (動作ログの記録と確認)

サーバ・クライアントの動作ログを `data/logs.db` (SQLite。設定用の `app.db` とは別) に記録し、
ツールバーの 🩺 (または設定 → 一般 → 「アプリログを開く」) から画面上で確認・検索できる。

- **ID による紐づけ**
  - **セッション ID**: ブラウザのタブ単位 (sessionStorage)。全 API に `x-session-id`、WS に `?session=` で送る。
  - **リクエスト ID**: HTTP リクエストごとにサーバが発行。レスポンスの `x-request-id` とエラー JSON の
    `requestId` に含める。エラートーストにも表示され、クリックするとそのリクエストのログが開く。
- **記録内容**: アクセスログ (メソッド / パス / ステータス / 所要時間)、エラー (スタック付き)、
  未捕捉例外 (`uncaughtException` / `unhandledRejection`)、WS の接続/切断、ブラウザ側の未捕捉例外や
  トーストに出したエラー (`POST /api/log/client`)。
- **検索**: 文字列 (メッセージ・詳細)、レベル (debug/info/warn/error 以上)、発生元 (サーバ/クライアント)、
  セッション ID (候補付き。「このタブのみ」ボタンあり)、リクエスト ID、期間。行クリックで詳細 (JSON・スタック) を展開。
- **保存期間**: 既定 30 日。設定 → 一般 → 「アプリログの保存期間 (日)」で変更。起動時と 1 時間ごとに古い行を削除する。
  「全削除」で即時に全消去も可能。
- 開発時、トーストに「サーバーに接続できません」と出る場合は Vite のプロキシがサーバに繋げていない
  (`node --watch` の再起動中、またはクラッシュ)。クラッシュならその直前のログが `uncaughtException` として残る。

## セキュリティ (plan §2.2)

- 127.0.0.1 のみで待受、Host/Origin 検証、`x-app-token` によるトークン必須。
- 削除は既定でゴミ箱送り (完全削除は確認付きの明示操作のみ)。

## メモ

- 設計書は macOS 前提だが、実装はクロスプラットフォーム (Windows ではドライブレターを
  ボリュームとして列挙、ゴミ箱はごみ箱に対応)。
- この環境では `tsx watch` が動作しないため、server の dev スクリプトは
  `node --watch --import tsx` を使用している。
